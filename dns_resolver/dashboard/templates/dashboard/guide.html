1 İki alan adı rolü

Domain'i iki ayrı iş için kullanırsın; ikisini karıştırma:

DNS servisidns.example.com → istemcilerin şifreli DNS için bağlandığı ad (DoT/DoH/DoQ). Sertifika bu ada göre. Panel (opsiyonel)panel.example.com → bu yönetim arayüzü (HTTP/HTTPS).

Aynı domaini ikisi için de kullanabilirsin ama ayrı alt alan daha temiz ve güvenli (paneli DNS'ten bağımsız koruyabilirsin).

✓

Bir A kaydı için sunucunun public IP'si gerekir. Public IP/port açmak istemiyorsan Cloudflare Tunnel bölümüne bak.

2 DNS kayıtları & Cloudflare proxy

Domain sağlayıcında (ör. Cloudflare) her kaydın proxy durumu kritik: DNS only · gri mi yoksa Proxied · turuncu mu. Cloudflare proxy'si yalnız HTTP(S) taşır.

DoT & DoQ (port 853) — proxy KAPALI

DoT/DoQ ham TLS/QUIC'tir, HTTP değil → proxy bunları taşıyamaz. Doğrudan A kaydı + açık 853 şart:

Kayıtdns.example.com  A  <sunucu-ip> ProxyDNS only · gri bulut Açık port853/tcp (DoT) + 853/udp (DoQ)
⚠️

Bu kaydı turuncu bırakırsan DoT/DoQ istemcileri bağlanamaz. Bulut gri olmalı.

DoH (port 443) — proxy AÇIK olabilir

DoH, HTTPS üzerindedir; tek istisna budur. Proxy açık ya da tünel ile çalışır:

Kayıtdns.example.com  A  <sunucu-ip> ProxyProxied · turuncu ya da tünel Adreshttps://dns.example.com/dns-query

Panel (443) — proxy AÇIK

Kayıtpanel.example.com  A/CNAME → sunucu / tünel ProxyProxied · turuncu (TLS + IP gizleme)
✓

Paneli Cloudflare Access (SSO / e-posta doğrulama) arkasına al — panel login'inin önüne ikinci kapı.

Özet

Yöntem   Std. port   Cloudflare proxy      Kayıt
DoT      853         ✗ KAPALI (gri bulut)   A → sunucu IP, 853 açık
DoQ      853/udp     ✗ KAPALI (gri bulut)   A → sunucu IP, 853/udp açık
DoH      443         ✓ AÇIK / tünel         A → sunucu IP ya da tünel
Panel    443         ✓ AÇIK / tünel         A/CNAME + Access
UDP      53          ✗ (proxy yok)          genelde public açılmaz
ℹ️

Kısa kural: DoT/DoQ = gri bulut, DoH/panel = turuncu ya da tünel.

3 Domain sertifikası

Şifreli yöntemler, bağladığın domaine ait geçerli bir TLS sertifikası ister. Sertifikanın adı (CN/SAN) istemcinin bağlandığı adla birebir aynı olmalı — yoksa istemci doğrulaması başarısız olur.

sudo certbot certonly --standalone -d dns.example.com
# çıktı: /etc/letsencrypt/live/dns.example.com/{fullchain,privkey}.pem
# bu dosyaları projedeki certificates/ altına koy

Ardından panelden bağla: DNS Ayarları → Sertifika → yolları gir → Doğrulama kartında GEÇERLİ + Özne (CN) = dns.example.com gör.

⚠️

Sertifika dns.example.com için ama istemci baska.example.com'a bağlanırsa TLS doğrulaması patlar. Cert adı = bağlanılan ad.

4 Bağla & doğrula

Kaydı + sertifikayı ayarladıktan sonra Sunucular'dan ilgili yöntemi aç, sonra domain üzerinden test et. İstemciler standart portları (DoT/DoQ 853, DoH 443) kullanır:

# DoT
kdig +tls @dns.example.com +tls-hostname=dns.example.com example.com

# DoQ
kdig +quic @dns.example.com example.com

# DoH
kdig +https @dns.example.com example.com
ℹ️

Dış (host) port eşlemen bu standart portları konteynerin iç dinleme portlarına yönlendirmeli: DoT 853→{{ ports.dot }}, DoH 443→{{ ports.doh }}, DoQ 853→{{ ports.doq }}. Eşleme compose.override.yml'dedir; iç portlar Sunucular sayfasından ayarlanır.

5 İstemciyi domaine yönlendir

Artık cihaz/uygulamalarda çözümleyici adresi olarak domaini gir:

AndroidAyarlar → Özel DNS (Private DNS) → dns.example.com (DoT) FirefoxAyarlar → DoH → Özel → https://dns.example.com/dns-query iOS/macOSDoH/DoT .mobileconfig profili (dns.example.com) AdGuard/Routerupstream: tls://dns.example.com · https://dns.example.com/dns-query
✓

Bir engelleyicinin (AdGuard Home / Pi-hole) arkasına recursive upstream olarak koyacaksan, dns-net içinde {{ container_ip }}:{{ ports.udp }} de kullanılabilir (domain gerekmez).

6 Cloudflare Tunnel (public IP/port yoksa)

Sunucuya doğrudan port açamıyorsan cloudflared tüneli DoH ve paneli yayınlayabilir; A kaydı/açık port gerekmez.

⚠️

Tünel HTTP-only'dir → yalnız DoH + panel çalışır. DoT/DoQ tünelden geçmez; onlar için doğrudan A kaydı (gri) + açık 853 şarttır.

7 Sık yapılan hatalar

  • DoT/DoQ kaydı turuncu (proxied): istemci bağlanamaz — gri bulut yap.
  • Sertifika adı ≠ bağlanılan ad: TLS doğrulama hatası — cert'i doğru domaine al.
  • Yalnız tünel + DoT beklemek: tünel DoT/DoQ taşımaz; doğrudan port aç.
  • 853 güvenlik duvarında kapalı: DoT/DoQ dışarıdan erişilemez — 853/tcp+udp aç.
  • Panel public + auth'suz: paneli tünel/proxy + Access ile koru, yalnız domain arkasına al.
